CONVERSATION · PERMALINK

Permalink Issue

A conversation permalink doesn't open, or opens the wrong thread.

RUN THE PLAY →
SETUP

Check Access & Refresh

  1. Check whether it's a Private or Public permalink.
  2. Confirm who's accessing it — are they part of the inbox or not?
  3. Log out and log back in.
  4. Check the auth status.
  5. Refresh the screen.
  6. Clear cookies and cache.
Most permalink issues trace back to access — not the link itself.
WORKFLOW · EXTENSION

Extension Isn't Loading

The Hiver Chrome extension won't load inside Gmail.

RUN THE PLAY →
SETUP

Reset the Extension

  1. Ask when the issue started.
  2. Refresh Gmail.
  3. Do a hard refresh.
  4. Clear cookies and cache.
  5. Check the Chrome version, or update Chrome.
  6. Uninstall and reinstall the extension from the Chrome Web Store.
  7. Try a new Chrome profile.
  8. Check internet connection, VPN, and DNS; try changing DNS to Google.
  9. Check for conflicting extensions and third-party applications.
  10. Check browser security settings (Brave, DuckDuckGo, etc.).
  11. Still unresolved? Collect network logs, Chrome version, and console logs, then escalate.
WORKFLOW · ACCOUNT

User Email Address Update

A user's email address has changed and their Hiver account needs to move with it.

RUN THE PLAY →

User email update - HIG

  1. Update the old email address to the new one in Google Workspace (e.g. old.email@company.com → new.email@company.com).
  2. Email Hiver Support confirming the Google Workspace update, with the Hiver Admin in CC.
  3. Hiver Support updates the account on their end.
  4. Log out of Hiver and log back in with the new email address.
  5. All existing Hiver data, settings, and history remain unchanged.
Google Workspace must be updated first — Hiver Support can't update ahead of it.
WORKFLOW · INBOX

Emails in Inbox

An email is showing up in the shared inbox that a customer says shouldn't be there — or vice versa.

RUN THE PLAY →

Trace the Delivery Path

  1. Note the shared inbox name (group or user).
  2. Identify the impacted user.
  3. Check the Copy to Inbox setting — the assigned user will also get the email in their own inbox.
  4. Check whether the email is inbound, outbound, or manually added.
  5. Check From, To, CC, and BCC for any mailing list addresses.
  6. Check if the affected user's email is in To, CC, BCC, or part of a mailing list.
  7. Check filters and forwarding.
  8. Check aliases.
  9. Check filters for "Never mark as spam" or "Skip Inbox" — enabled or missing.
  10. Check thread analysis and look for the Inbox label.

WORKFLOW · SENDER SETTINGS

My Sent Error

Customer sees an error related to My Sent, or emails aren't sending as the expected address.

RUN THE PLAY →

Verify the Sender

  1. Ask for a full-page screenshot showing the issue.
  2. Check whether an error message appears.
  3. Check Sender Settings under My Settings.
  4. Go to Gmail Settings → Accounts → Send mail as.
  5. Ensure the name and email address in Send mail as match My Sent under My Settings.

  8. Refresh the page and test again.
WORKFLOW · EMAIL SYNC

Email Sync - Group Type

Emails sent to a Google Group aren't syncing correctly into Hiver.

RUN THE PLAY →

Trace the Group Sync

  1. Identify the source user associated with the Google Group and check their authentication status in Grexit Admin.
  2. Check authentication status: Source = -1 means the source user isn't authenticated; Source = -0 means check the Google Group settings.
  3. Ask the customer to log in at group.google.com and verify the group settings are configured correctly.
  4. Verify the subscription status of the source email address in Google Groups, for each relevant address.
  5. Send a test email to the Google Group and confirm whether it's delivered to the source user's Gmail inbox.
  6. Run a thread-level analysis to see where the flow breaks — did it reach the source user, and was it then processed by Hiver?
  7. If the source user isn't receiving the email, check Gmail forwarding settings and filters that may be moving, deleting, or otherwise affecting it.
  8. If all checks above pass, try changing the source user to another authenticated group member and send another test email.
  9. Escalate if the source user receives the email, authentication and group settings are correct, no forwarding/filters interfere, changing the source user doesn't help, and it's still not syncing.
WORKFLOW · AUTH STATUS

Auth Status in Grexit Admin

Reference for reading a user's authentication status in Grexit Admin.

RUN THE PLAY →

The 3 Auth Statuses

  1. 0: User is logged in Hiver.
  2. -1: User is logged out of Hiver.
  3. -2: User has removed Hiver and revoked Hiver's access, and we have lost all authentication.
WORKFLOW · RLE

RLE

Rate Limit Error — a Gmail-side limit that stops sync, status changes, and API calls.

RUN THE PLAY →

Check & Communicate

  1. RLE stands for Rate Limit Error, applied by Gmail.
  2. If RLE is hit: sync won't work, status won't change, and API calls won't happen.
  3. To check if RLE was hit in the last 24 hours, go to Grexit Admin → Users → RLE.
  4. If RLE was hit in the last 24 hours, the system will recover on its own — tell the CX it was hit and is recovering.
  5. If RLE shows red in the GA column, inform the CX it's been hit and will regulate within 24 hours.
  6. The rate limit is managed by Gmail — the system regulates and recovers automatically once the limit resets.
"I completely understand how important it is to have your emails syncing smoothly, especially when you rely on Hiver for your day-to-day communication. Since this rate limit is controlled by Gmail, it will automatically reset within the next 24 hours, after which the email sync will resume normally. At this point, the best course is to allow Gmail's rate limit to reset, and the system will recover automatically once that happens."

WORKFLOW · EMAIL SYNC

Email Sync - Delay

Emails are syncing later than expected and you need to find out where the delay is coming from.

RUN THE PLAY →

Locate the Delay

  1. Email sync delay can be caused by either Hiver or Gmail.
  2. Gather the impacted Thread ID.
  3. Check the email header in Google Toolbox (toolbox.googleapps.com/apps/messageheader/analyzeheader).
  4. 300342089616 is Hiver's ID.
  5. If the delay is before this ID, it's from Gmail. If it's after this ID, it's from Hiver.
  6. If the CX is reporting a live delay, send a test email and wait for it to sync.
  7. Check the timestamps and determine the delay based on them.
  8. Escalate accordingly.
WORKFLOW · EMAIL SYNC

Email Sync - User Type

Checking whether an email has synced, and troubleshooting when it hasn't.

RUN THE PLAY →

Check & Trace the Sync

  1. To check if it synced: send a test email to the shared mailbox.
  2. Run the Thread Analysis (TA).
  3. If the labels are applied, the email has synced.
  4. Check the details under Other Details in TA.
  5. If sync isn't working, check the Auth Status in Grexit Admin.
  6. Ask the CX if the email is being received in the root account.
  7. If it's still not received, redirect the CX to Gmail and explain that emails aren't received in the Gmail account itself.
  8. If it IS received in the root account: revoke the shared mailbox's authentication, have the user log in again, and check for third-party apps/extensions — escalate if it continues.
  9. If it's NOT received in the root account: check Gmail filters, check Spam and Trash, and check the RLE status.
WORKFLOW · EMAIL SYNC

Email Sync - Alias

An alias address isn't syncing correctly to the shared mailbox.

RUN THE PLAY →

Trace the Alias Flow

  1. Gather the Thread ID and run the Thread Analysis (TA).
  2. Check if the source user has received the email, and check the source user in Grexit Admin.
  3. Send a test email to the alias and check if the source user receives it.
  4. Verify the alias is declared in both Gmail and Hiver (e.g. Support@xyz is the SM/source user, Saleena@abc is the alias — mail to Saleena@abc should land at Support@xyz, then sync to the shared mailbox).
  5. If the source user does NOT receive the email: check RLE status, authentication status, Gmail filters, and Spam/Trash — redirect the CX to Gmail if everything checks out and it's still not arriving.
  6. If the source user IS receiving the email but it's not syncing to the shared mailbox: gather the Message ID, check for third-party apps/extensions, and escalate with the Message ID and all relevant details.
WORKFLOW · OMNI

"Undo Send" in Omni

Yes, Omni supports Undo Send.

RUN THE PLAY →

Set Up Undo Send

  1. Go to My Settings → Basic Settings → Undo Send, then select your preferred timer (5, 10, 20, or 30 seconds).
  2. After sending an email, click Undo within that time window to stop it from being sent.
  3. Important: Once the selected timer expires and the email has been sent, it cannot be undone or recalled.
WORKFLOW · INTEGRATIONS

Send Notification to Slack

Connect Hiver with Slack to receive instant notifications about activity in your Shared Inboxes without switching between tools.

RUN THE PLAY →

Connect & Configure

  1. Before you begin, make sure you have: Hiver Admin access, access to the Slack workspace you want to connect, and the Shared Inbox you want to connect.
  2. Go to Hiver → Settings → Admin Panel → Integrations → Apps.
  3. Select Slack.
  4. Choose the Shared Inbox you want to connect.
  5. Turn on the Connect Slack toggle.
  6. Sign in to your Slack workspace in the new tab.
  7. Select your workspace and click Install Hiver.
  8. Configure notifications — choose from: new conversations, assignments, @mentions in notes.
  9. Select the Slack channel where you want notifications to appear, then click Enable.
  10. Note: the Hiver–Slack integration is notification-only. You can receive Hiver updates in Slack, but Hiver actions must be performed in Hiver.
WORKFLOW · INTEGRATIONS

Collaborate via Slack

Use Hiver's Slack integration to get help from your product, engineering, finance, or other teams without leaving Hiver.

RUN THE PLAY →

Set Up & Start a Discussion

  1. You can: start a discussion in an existing Slack channel or create a new one; view and reply to Slack messages directly from Hiver; get notified about new messages and mentions.
  2. Before you begin, you need: Hiver Admin access to set up the Slack app, and access to the Slack workspace you want to connect.
  3. Set up Slack: go to Admin Panel → Integrations → Apps.
  4. Select Slack and click Start setup.
  5. Choose the Shared Inboxes where Slack should be available.
  6. Select the roles that can use Slack.
  7. Click Save configuration.
  8. Connect your Slack account: open a conversation and go to Slack.
  9. Click Connect Slack.
  10. Sign in to Slack, select your workspace, and click Allow.
  11. Start a discussion: click Start discussion.
  12. Choose an existing Slack channel or create a new one.
  13. Enter your message and click Send to Slack.
  14. Once connected, you can view and reply to the Slack thread directly from Hiver. The conversation assignee is notified when there are new messages or mentions.
